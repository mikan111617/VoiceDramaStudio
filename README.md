# VoiceDrama Studio — 台本から音声ドラマへ

Windowsで使える、**ローカルのボイスドラマ制作ツール（初期実装版 v0.2.9）**です。台本（Excel）の加筆修正と、台詞に紐づく音声テイク、BGM／効果音／環境音の複数トラック編集を一つの画面にまとめました。

**この版は動作する初期版です。** 音声編集機能とTTSモデルの実機動作確認の範囲は異なります。「確認済み」の範囲は後述します。

## 起動方法（Windows）

1. Python **3.10以降**を入れます（インストーラで「Add Python to PATH」を有効に）。
2. このZIPを展開します。できれば `C:\VoiceDramaStudio` のような日本語文字の少ないフォルダに置きます。
3. **`start_windows.bat`** をダブルクリックします。初回は依存ライブラリを自動インストールします。起動バッチは文字コードの誤認識を避けるためASCII文字のみを使用しています。
4. ブラウザで `http://127.0.0.1:8765` が開きます。開かない場合は手動でアクセスしてください。**アプリ本体は手元のPCだけで動きます。**
5. 最初のプロジェクトが自動的に作成されます。上部のプロジェクト名から別作品を追加できます。

**起動時に文字化け・コマンド未認識が出た場合:** v0.1.1以降の `start_windows.bat` を使用してください。バッチをZIPのプレビュー画面から直接起動せず、必ず「すべて展開」したフォルダから起動してください。既存プロジェクトを保持するには以前の `VoiceDramaStudio` フォルダのバッチファイルのみ上書きして構いません。

音声のWAV/MP3書き出し、およびMP3/M4A等の安定した取り込みのため、[FFmpeg](https://ffmpeg.org/) をインストールして `ffmpeg` と `ffprobe` にPATHを通すことを推奨します。FFmpegなしでもWAV素材を読み込んでWAVミックスを書き出せます。

macOS/Linuxでは `./start_unix.sh` でも起動可能ですが、TTS側のPython環境は別途用意してください。

## 画面の使い方

- **シナリオ**: セリフの追加・並べ替え・修正、話者・演技指示・台詞後の間を編集します。「要生成を一括」で未生成・要再生成の台詞をまとめて生成できます。
- **Excel取り込み**: `↑ Excel取込` から `.xlsx` を読み込みます。変更箇所だけ編集画面に反映され、既存の音声を自動削除しません。
- **Excel書き出し**: 右上から、次回インポート用に台詞ID付きのExcelを保存します。
- **音声ライブラリ**: WAV/MP3等をドラッグ＆ドロップ・一括登録し、台詞へ順番に割り当てたり、BGM・効果音・環境音トラックに追加します。
- **マルチトラック**: 音声クリップをドラッグで移動、右端をドラッグで長さ変更。クリック後は下部インスペクタで音量・フェード・ループ・トリミング・開始位置を設定します。
- **台詞を自動整列**: 右下のボタンで、台詞と次の台詞の間を計算して並べ直します。手で移動したクリップは「固定」になり、自動整列では動きません。
- **音声書き出し**: WAVまたはMP3。現在のシーンだけ、あるいはシーンを順に連結して出力できます。
- **再生**: Web Audioで複数トラックを同期してプレビューできます。

### Excel形式

最初の見出し行に次の列を用意します。列順は自由です。1シートにつき1シーンとしても、`シーン` 列でシーンを指定しても構いません。

| 台詞ID | シーン | 話者 | 台詞 | キャプション | 間(秒) |
|--|--|--|--|--|--|
| *(初回は空でOK)* | 第一幕 | 真歩流 | サブレがない！ | 周囲を見回しながら驚いて | 0.6 |
| *(初回は空でOK)* | 第一幕 | 愛理 | 知らないわよ。 | 平静を装う | 0.8 |

**重要**: IDのない台本も読み込めますが、あとで修正して再インポートする際は、一度アプリから**台詞ID付きExcelを書き出して、そのファイルを更新**してください。IDがない場合、完全一致する話者＋本文＋シーンだけを既存台詞と同一視します。既存台詞を消すのではなく、安全側で新規行として取り込みます。Excelの再インポートで見つからなかった台詞は自動削除しません。

## v0.1.2：既存音声のドラッグ＆ドロップと一括割り当て

**すでに生成済みの台詞音声をまとめて読み込めます。** モデルの導入は不要です。

1. 作品を開き、**シナリオ**の「**既存音声を一括割当**」を押すか、画面の点線枠へWAV/MP3等をドラッグ＆ドロップします。複数ファイルを一度に選択できます。
2. 確認画面で、**シーン**と**開始台詞**を指定します。音声のない台詞だけに割り当てる設定が初期状態で有効です。
3. 音声は初期状態でファイル名の自然順に並びます（例：`voice_1.wav`、`voice_2.wav`、`voice_10.wav`）。ファイル名にアプリ固有の台詞ID（例：`line_1234...`）が含まれる場合、その台詞を優先して照合します。通常のファイル名は数字順などで並べ、その順番で台詞を割り当てます。
4. 一覧の「割り当て先」から、**1ファイルずつ個別に指定・解除**できます。↑↓ボタンでファイル順も修正できます。台詞が足りない分は「素材のみ」で保存します。
5. 内容を確認して「**取り込む**」を押します。元音声をコピーしてプロジェクトに保存し、台詞に新しいテイクとして紐付け、タイムラインに自動で並べます。

**キャストの参照音声**として取り込む場合は、左側の「**キャスト・声**」を開き、**キャストカードへファイルをドロップ**してください。複数の参照音声をまとめて登録できます。カード以外の点線枠にドロップした場合は、確認画面から登録先のキャストを選択してください。

**BGM・効果音・環境音をまとめて追加**するときは、「**音声ライブラリ**」で一括取り込み → 取り込み方法「音声ライブラリに保存する」→ 音声の種類を選んでください。取り込んだ後、ライブラリから好きなトラックへ追加できます。

**安全仕様:** 既存のテイクを削除・上書きしません。同じ台詞への重複割り当ては確認画面で検出し、取り込みを停止します。登録先や音声形式の検証でエラーが発生した場合は、プロジェクトを変更しません。1回250ファイルまで、1ファイル250MB／合計1GBまで。MP3/M4Aなどの取り込みは、環境によってFFmpeg/ffprobeが必要です。

**旧バージョンからの更新:** 初めて使う場合は解凍したフォルダの`start_windows.bat`で起動してください。v0.1.1で作った作品を引き継ぐ場合は、古い`VoiceDramaStudio/workspace`フォルダを新バージョンの同じ場所へコピーしてください（古いフォルダはバックアップとして残すことをおすすめします）。`workspace`内のプロジェクトデータは新バージョンと互換です。

## Irodori-TTSを使う

このアプリにモデル本体は同梱しません。既存の **Irodori-TTS** 環境（`infer.py` と `.venv`）をそのまま利用する設計です。

1. 公式 [Irodori-TTS](https://github.com/Aratako/Irodori-TTS) を別途導入し、公式の単発音声生成ができる状態にします。
2. 右上の **設定** で `Irodori-TTS` フォルダを指定します（既定は `D:\Irodori-TTS`）。Pythonのパスが異なる場合はそれも指定します。
3. **キャスト・声** からキャラクターを作り、既存の参照WAVを登録するか、Voice Design用の声の説明を書いて **「Voice Designで新しい声を作成」** を押します。生成した声はキャストの参照音声に保存され、次の台詞の声の複製に利用できます。
4. **シナリオ** で台詞を選択すると下部にTTS設定が出ます。エンジン・モデル・参照音声方式を選び「音声生成」を押します。
5. アプリは依存環境を分けたプロセスでリクエストを送ります。**同じモデルの複数台詞は一度のモデルロードで連続生成**します。

選択候補: `Aratako/Irodori-TTS-v4.1-Small`、`Aratako/Irodori-TTS-v4-Large`、`phasefield-audio/Irodori-TTS-v4.1-Anime`。Large/Animeの量子化INT8もモデル欄から選択できます。その他の量子化版や派生モデルは「その他（直接入力）」からチェックポイントIDを指定できます。量子化チェックポイントでは公式の指定に合わせ、モデル精度 `bf16` で読み込みます。モデルによっては現在の`infer.py`の更新が必要です。v4-Largeの通常版はRTX 4070 12GBではメモリ不足になる可能性があるため、量子化版などを検討してください。

Irodori専用ワーカーは添付された `voice_pipeline_v28.py` の、**公式`infer.py`を呼びつつ推論ランタイムを使い回す方式**を参考にしています。現在の版は一括生成時のモデルキャッシュに対応していますが、参照音声latentのディスクキャッシュなど、元コードのすべての機能を移植したものではありません。

## Qwen3-TTSを使う

Qwenは**別のPython仮想環境**を利用します。既存のQwen実行環境がある場合はその `python.exe` を設定すれば使えます。

新規導入する場合の基本例:

```bat
py -3 -m venv .venv-qwen3tts
.venv-qwen3tts\Scripts\python.exe -m pip install --upgrade pip
.venv-qwen3tts\Scripts\python.exe -m pip install qwen-tts soundfile
```

**注意**: CUDA対応PyTorchやモデル依存パッケージの構成はGPU/ドライバにより異なり、公式Qwenの手順で導入・検証してください。これらをこのアプリから自動導入する機能はまだありません。モデルのダウンロードにはネット接続と十分なストレージが必要です。QwenのVoice Designから声を作り、参照音声としてキャストへ登録すると、その後のBaseモデルによるクローンに使えます。

- **Base**: 参照WAVが必要です。キャストで参照音声と、分かる場合はその読み上げ書き起こしを登録します。書き起こしが空の場合は`x_vector_only_mode=True`を使います。
- **Voice Design**: 参照音声なしでもキャストの「声の説明」＋台詞の演技指示から生成できます。Qwen VoiceDesignモデルを選択します。
- 日本語・英語を選択できます（台詞の言語設定）。
- Voice Designで生成した音声を声の参照に利用したい場合は、音声ライブラリ内の生成済みWAVをキャストの参照音声として選べます。

RTX 4070 12GBではモデルの組み合わせにより推論時VRAM容量が不足する可能性があります。一度に1エンジン／1モデルで処理し、終了後にGPUメモリを解放する設計です。

## 任意: Ollamaによる演技指示の提案

Ollamaをインストール・起動した場合、台詞の下部から **演技指示を提案** を選択できます。前後3台詞の文脈を送り、キャプションの候補を取得します。モデル名は任意です。元の `voice_pipeline_v28.py` にある、作品設定・全体の状態遷移を継続的に管理する高度な解析は**この版には未移植**です。取得結果を人が確認して修正してください。

## 保守・データ構造

プロジェクトは `workspace/p_.../` に保存されます。

```
workspace/
  p_.../
    project.json     ← ID、台詞、声、トラック、クリップ、テイク履歴
    assets/          ← 元音声・生成音声のコピー
    exports/         ← WAV / MP3の書き出し結果
```

- 台詞ごとに固有IDを付け、音声テイクとクリップを関連付けます。
- 台詞が修正されたら音声を消さず、必要に応じて「要再生成」にします。
- 再生成時には新しい素材を登録し、過去のテイクは保持します。
- プロジェクトJSONは更新時に一時ファイルへ書いてから置換します。
- 保存APIではリビジョン競合を検出します。保存中にほかのブラウザから同時編集しないでください。
- GUIとTTSワーカーは別プロセスで実行し、GUIのPython環境からモデル依存ライブラリを直接importしません。

## v0.1.3: 声の参照音声と台詞音声の分離・音声ゴミ箱・新規プロジェクト

- **キャスト・声**では `reference` 素材のみ候補に表示します。旧版でキャストへ結びつけた台詞用 `voice` 素材は「⚠ 旧登録」として表示し、チェックを外すことで解除できます。既存の音声ファイルを勝手に消したり、種類を自動変更したりはしません。
- **音声ライブラリ**は台詞・BGM・効果音などの素材を表示し、キャラクター用の参照音声とは分離します。参照音声の管理と削除は「キャスト・声」から行えます。
- **新規プロジェクト**：画面上部の作品名をクリック → 「新規プロジェクト」へタイトルを入力 → 「新規作成」。以前は画面上の実行ハンドラーが欠けていました。
- **誤アップロード**：対象音声の「🗑 削除」を選びます。キャスト・台詞・トラックで使用している場合は参照件数を表示し、承認後に紐付けを解除します。ファイルは `workspace/<project>/trash/` へ移動します。
- **復元**：「音声ライブラリ」→「ゴミ箱を確認・復元」で復元できます。復元するのは音声ファイルと素材情報のみです。以前の台詞・キャストへの割り当ては必要に応じて付け直してください。
- 新しいGitリポジトリでは `workspace/` をバージョン管理しないでください。既にGitで追跡されているファイルは `.gitignore` を変更しても公開履歴から消えません。必要ならGitHubの公開履歴も含めて別途除去してください。

- 音声ライブラリの各素材に「選択」チェックを追加しました。「🗑 選択削除」で誤って取り込んだ**未使用**の複数ファイルをまとめてゴミ箱へ移動できます。1件でもキャスト・台詞・タイムラインで使用中なら一括削除は中止します。使用中の素材は個別の「削除」から確認してください。


## v0.1.4: 複数プロジェクト間のキャスト・声設定コピー

「キャスト・声」→「⇄ キャストを別作品へコピー」で、1件・複数件・全件を選択して別プロジェクトへコピーできます。キャストカードの「⇄ 別作品へコピー」なら、その1件が最初から選択されます。

- コピーされるもの：名前、言語、音声エンジン、モデル、生成方式、Voice Designの説明、Qwenの書き起こし、キャラクター参照音声（音声ファイル自体をコピー）。
- コピーされないもの：台本・台詞・音声テイク・タイムライン・BGM・効果音・プロジェクト全体の設定。
- コピー先を既存プロジェクトから選ぶか、新規プロジェクトを作成できます。
- 同名キャストの扱いは「スキップ」または「コピー名で新規登録」を選択できます。既存キャストの上書きは行いません。
- 参照音声はコピー先の独立した音声素材として保存し、IDを付け替えます。元プロジェクトの音声を削除してもコピー先には影響しません（保存容量は増えます）。
- コピー途中で失敗した場合はコピー先の新規音声ファイルを掃除し、保存情報を変更しません。複数キャストが共通の参照音声を使用している場合、対象プロジェクトへのコピーは1回だけ行います。

## v0.1.7: Excelシナリオの全件置き換え

「シナリオ」→「↑ Excel取込」から取り込み方式を選択できます。

- **追加・更新**（初期選択）: Excelにない既存台詞・シーンを残す従来方式。
- **シナリオをすべて置き換える**: Excel内にない台詞とシーンを取り除く。該当する台詞と紐付いたクリップ、削除シーンのクリップも取り除く。キャスト設定・登録済み音声素材・参照音声は削除しない。同じIDの台詞はテイク履歴を維持する。
- 全件置き換え前には `workspace/<project_id>/backups/before_excel_replace_....json` に旧プロジェクト情報をバックアップ（音声ファイルは移動・削除しない）。バックアップを戻すには、アプリを閉じてから対象の `project.json` をバックアップして、バックアップJSONで置き換えられます（音声ファイルを消していない場合）。
- Excelに台詞列が存在しないシート、台詞が0件、ID重複などがある場合は全件置き換えを中止する。編集競合も検出する。置き換え前に確認ダイアログを表示。
- **注意:** 維持されたシーンにある独立したBGM/効果音クリップは残ります。新しい台詞のタイミングに合わせ、必要に応じて調整してください。

## v0.1.8: キャスト設定を台詞へ自動適用

「キャスト・声」でIrodori Animeなどを指定すると、そのキャラクターの台詞は既定で同じモデルを使います。新規台詞だけでなく、旧版が各台詞に自動入力していたSmallの初期値もキャスト設定を優先します。明示的な個別モデルを使用したい場合のみ、台詞を選んで「音声生成の設定元」→「この台詞だけ個別設定」を選択してください。旧版でSmall以外に変更した台詞は原則として個別設定を維持します。

「このキャストの全台詞へ設定を適用」ボタンは、選択したキャストの全台詞を参照モードに切り替えます。生成前にはIrodori/Qwenごとの**実際に使用するモデルと件数**が表示され、確認後に生成できます。旧版で開始した生成ジョブは引き継がれないため、更新時はアプリを終了してから再起動してください。

## v0.1.9: シナリオをすべて削除

## v0.2.9: 独立した「ゲーム音声」制作タブ（KS / 音声リストJSON）

上部の **「🎮 ゲーム音声」** から開きます（URL: `/game`）。既存のボイスドラマ制作とは**別プロジェクト・別の音声保存先**になっており、ゲーム側で編集してもボイスドラマの台本・マルチトラック・生成音声は変更されません。TTSのインストール先は従来の全作品共通設定を使用します。キャストの声・参照音声は、ボイスドラマの既存プロジェクトから話者ごとに割り当てて再利用できます（元プロジェクト側のキャストが削除された場合は再設定が必要です）。

### 最初の使い方

1. ゲーム音声タブで「＋」からゲームプロジェクトを作成します。
2. 以前の `.voice_id_state.json` を使う場合は、**KSを取り込む前に**「voice ID履歴を読み込む」から選びます。添付サンプルの `last_issued: 3958` なら新IDは `v03959` から始まります。
3. 「シナリオ .ks」からTyranoScriptを取り込みます。複数ファイルを一括選択できます。`#話者` / `[p]` / `[l]` 形式の発話を抽出し、中央に**原文（行番号）と台詞・voice ID一覧**を表示します。ユーザーが以前生成した `[voice id="..."]` があれば維持します。同じ話者と台詞の再取り込みではIDを再利用し、単純な本文修正でも可能な範囲でIDを維持します。
4. 「キャラクターシート」で `character_sheet_v3.json` を読み込むと、表示名・読み・基本トーン・演技メモをインスペクタに表示します。「作品コンテキストJSON」の取り込みも任意です。
5. 台詞をクリックし、元原文とは別の「読み上げテキスト」と「演技指示」を確認・編集します。保存ボタンで保存します。**オリジナルのKSは一切上書きしません**。
6. 右側の「CAST ASSIGNMENTS」でゲーム話者IDごとにボイスドラマ側のキャスト（音声モデルと参照WAV）を割り当てます。台詞にチェックを入れ、「選択分を生成」でTTS音声を生成します。Irodori/Qwenの既存Python環境が必要です。ゲーム用の音声は `workspace/game_voice/<game-id>/audio/` へ分離保存します。
7. 必要に応じて「演技指示を解析」を押し、ローカルのOllamaから演技指示をJSONで取得できます。既定モデルは元ツールと同じ `gemma4:12b`（モデル導入と起動はユーザー側で行います）。**元ツールの高度な差分LLMキャッシュ・ASR品質ゲート・全ルート自動解析を完全移植したものではありません**。演技指示の自動生成は補助機能なので、画面で確認・修正してください。
8. 「ゲーム用ZIP」を押すと音声と `[voice id="v00001"]` を付けたKSのコピー、およびボイスマップ・voice ID履歴をまとめて書き出せます。

### ゲーム向けZIPの構造

```text
voiced_scenarios/scene1.ks              元のKSを保ったボイスID付きコピー
voice_maps/scene1.json                  シーン内 voice ID → 相対音声パス
audio/mahoru/scene1/v03959.wav           キャラクター / シナリオ / voice ID
voice_map.json                           全シナリオの統合voice IDマップ
voice_id_registry.json                   voice IDの発行・シナリオ対応情報
.voice_id_state.json                     次の発行番号を引き継ぐための状態
missing_voices.json                      未生成または要再生成のvoice ID
```

音声の書き出し形式はWAV（初期値）またはMP3（FFmpegが必要）を選べます。ゲーム側の音声検索ルートが `voice/<話者>/<シナリオ>/<ID>.<拡張子>` の場合、ZIPの `audio` 配下をゲームの `data/sound/voice` へ配置します。`voiced_scenarios` のKSをゲームの `data/scenario` など適切な場所へコピーします。**既存ゲームの同名ファイルを上書きする前にはバックアップを取ってください。** `[voice]` の再生処理はゲーム側の実装が必要で、元の独自voiceタグ解決・voiceマップ処理を自動で置換するものではありません。

### voice-list JSONモード

添付の `voice_list_all_characters.json` のように `speakers[].speaker` と `items[].id` / `text` を持つJSONを「ボイスリスト JSON」で取り込めます。音声名は**元リストのIDを維持**し、例 `audio/mahoru/doubt_0.wav` のように出力します。内部では重複しない `v00001` 型の管理用voice IDも割り振ります。voice mapのルート名はJSONの `output_dir` 最終フォルダ名（添付例 `voice_en`）を引き継ぎます。JSONには元のKS原文が存在しないため、このモードだけでは `voiced_scenarios/*.ks` は生成しません。元のvoice-list JSONのコピー、生成音声、voice map、missing一覧を出力します。外部パス `reference_wav` に指定されている実ファイルは勝手に読み込みません。「CAST ASSIGNMENTS」から既存キャストと参照音声を紐付けてください。

### 安全・制約

- `.ks` の文字コードはUTF-8 BOM/UTF-8/CP932を認識し、元の文字コードと改行を保持して生成コピーへ書き出します。
- KS本文に1行で複数発話が詰め込まれ、IDを安全に挿入できない場合は取り込みを止めます。
- 既存ファイルを入力とする取り込みは保存リビジョンを確認し、別タブでの競合を防ぎます。重複ボイスIDも検出します。
- TTSで新しい音声を生成しても、ボイスドラマ側の音声・台本には書き込みません。
- 現段階では元ツールv28の全機能を移植したものではなく、ゲーム音声の取り込み・ID管理・演技指示の編集/補助・TTS生成・ゲーム用書き出しに重点を置いた独立モードです。


## v0.3.0: ChatGPT・ClaudeによるキャプションCSVの往復編集

ゲーム音声タブに「↓ このシナリオのCSV」「↓ 全シナリオのCSV」「↑ 記入済みCSVを反映」「AIへの依頼文をコピー」を追加しました。CSVはWindows Excelでも文字化けしにくいUTF-8 BOM形式で、**ボイスID、シナリオ、キャラ名、セリフ、キャプション**の5列を出力します。ChatGPTやClaudeにCSVを添付し、キャプション列だけを記入したCSVを返してもらい、再取り込みできます。追加のOllama実行は不要です。

## v0.3.3: ゲーム音声でキャラクター以外を自動除外

TyranoScript の `#TIPS` は、システムメッセージであって音声化対象のキャラクターではありません。ゲーム音声ではキャラクターシート未登録時でも `#TIPS` を自動的に除外します。キャラクターシートを取り込むと、`characters` と `reference_characters` 内のID・表示名・aliasesに該当する話者のみをKSの音声化対象とします。`non_character_speakers` の話者と未登録話者は除外します。

**取り込み済みのKSも対応**: 後からキャラクターシートを取り込むと、既存のゲーム音声の一覧から対象外話者を取り除き、対象件数を更新します。元のKS、保存済み音声ファイル、既存のキャラクターのボイスIDは書き換え・削除しません。未使用の発行済みIDは再利用しません。ボイスリストJSONは、明示的に音声化対象として指定したファイルなので、このKS用フィルタを適用しません。キャラクターシートに載っていないモブ・ナレーターも読み上げたい場合は、その話者を `characters` または `reference_characters` に追加してください。


## v0.3.4: キャラクターシートの参考人物をキャスト一覧にも表示

ゲーム音声の「キャスト割り当て」には、シナリオに台詞がある話者だけでなく、`characters` と `reference_characters` の登録者をすべて表示します。まだ対象の台詞がKSに見つからない人物は「シート登録済み・台詞未検出」と表示し、誤って音声を生成しません。自動対応の対象にも含めます。話者の別名（aliases）からキャラクターシートを参照でき、シートの正規IDへキャストを割り当てておけば、別名で登場する台詞の生成にも使用できます。

古い `voice_pipeline_v28.py` ではアーサーの話者IDに `arther`、舞黒邦夢の話者IDに `maicro` を使用しています。配布する更新済みキャラクターシートではそれぞれの `aliases` へ追加しています。元の人物設定の内容は変更せず、必要な場合だけ差し替えてください。


## v0.3.5: キャラクターシート更新時の欠落台詞を復旧

旧形式キャラクターシートで `prologue.ks` などを取り込むと、参考人物の話者ID（`arther`、`maicro`）が対象外になり、KS自体に台詞があってもキャスト一覧に「台詞未検出」と表示されることがありました。従来は後からキャラクターシートに `aliases` を追加しても、いったん除外された台詞が復元されませんでした。

この版では、キャラクターシートを再取り込みする際に**保存済みのKS原文からすべての対象台詞を再抽出**し、追加認識した人物の台詞を自動復旧します。KSに書かれたボイスIDは優先保持し、すでに登録済みの他のキャラクターの演技指示・生成音声を維持します。TIPS等のシステム説明は引き続き除外し、元のKS・音声ファイルは変更しません。シート登録後にKSを再アップロードする必要はありません。

`prologue.ks` と新しいキャラクターシートを照合する場合は、アーサー `arther` 15台詞、舞黒邦夢 `maicro` 10台詞、結月 `yuduki` 10台詞を音声化対象として表示できます。


## v0.3.6: 全シナリオのボイスIDを確定してから生成

ゲーム音声タブのKS取り込みを**「① KSを仮登録」→「② 全KSのボイスIDを一括確定」**の二段階に変更しました。最大30ファイル（各20MB、合計60MB）を複数回に分けて仮登録できます。仮登録中は**新規のvoice IDをまだ発行せず**、KS本文だけをプロジェクトに保存します。必要なsceneをすべて揃えてから一括確定してください。

確定時には、(1)登録済みシナリオと仮登録した全KSを読み込み、(2) `[voice id="..."]` の**明示IDを全作品から先に予約**し、(3)既存の自動発行IDは衝突しない限り維持、(4)新規台詞に未使用の連番を割り当てます。新しいKSの明示IDが、過去に別sceneへ自動発行したIDと衝突しても、**自動発行側を新しいIDへ変更して解決**します。既存のキャプション・読み上げテキスト・音声ファイルの保存パスは保持します（ゲームへ出力するときの音声ファイル名は新IDに変更）。変更されたIDは左ペインに表示し、出力ZIPに `id_remaps.json` も保存します。

**元のKSファイル自体に同じ明示IDが2つ存在する場合は自動改番しません。** どちらのIDが正しいかを推測できないため、ファイル名と行番号を表示して取り込みを中止します。ゲームの参照先が変わるため、過去に出力したボイスID一覧やキャプションCSVは、改番後に**必ず新しく出力し直してください**。

仮登録中のKSがある場合、誤ったIDで生成しないよう、音声生成とゲーム用ZIP出力を制限します。既存のAPI `/import-ks` は互換性のため残していますが、こちらも全登録済みKSを横断してIDを再照合します。画面からは仮登録方式を利用します。


## v0.3.7: ゲーム音声のキャラクター別・独立したTTS設定

ゲーム音声タブのCAST ASSIGNMENTSで、キャラクターごとに**「ボイスドラマのキャストを利用」**または**「ゲーム音声専用の声設定」**を選べます。ゲーム専用の声設定では、ボイスドラマと同じ Irodori/Qwenモデル、生成方式（参照音声/Voice Design）、言語、声の説明、Qwen用参照文字起こしを編集できます。参照音声はキャラクター単位でゲームプロジェクトの `reference_audio/` に登録し、試聴・削除できます。Voice Designで作った声もゲーム内参照音声として保存・試聴できます。

音声生成はキャラクターごとの設定元に応じて行われ、既存のボイスドラマのキャスト設定や参照音声を上書きしません。シナリオとボイスID、CSV、音声出力の形式は従来どおりです。ゲーム専用設定から共有キャストに戻しても、専用設定は保存されたままです。


## v0.3.8: ゲーム音声の話者別一括選択と左側キャスト設定

「ゲーム音声」モードのVOICE LINESに**話者でまとめて選ぶ**を追加しました。選択中のシナリオに登場する話者をドロップダウンで選択し、**この話者を選択**／**この話者を解除**からその人物の台詞だけチェックを切り替えます。検索で一覧が絞り込まれていても、対象はシナリオ内のその人物の全台詞です。シナリオ外の選択は変更しません。従来の「このシナリオを全件選択」も残し、選択件数を表示します。

左側に **「シナリオ・管理」「キャラクター・声」** の切替タブを追加し、これまで右側にあったキャスト割り当て、ゲーム専用声設定、モデル/言語/参照音声/Voice Designの管理を「キャラクター・声」へ移動しました。右側はセリフのインスペクターとGAME BUILDに集中します。音声ファイル・ID・キャスト情報・生成APIの仕様は変更しません。

## v0.3.9: ゲーム音声の読み方・アクセント辞書

ゲーム音声モードの左ペインに **「🗣 読み方・アクセント」** タブを追加しました。**ボイスドラマのプロジェクトとは別々に**、ゲーム音声プロジェクトごとに発音設定を保存します。

1. 「↑ 読み方JSONを取り込む」に、従来の `pronunciation_dictionary.json` （`{"舞黒館":"まいくろかん"}` のような辞書）を取り込みます。
2. 「↑ アクセントJSONを取り込む」に、従来の `prosody_dictionary.json` （`{"version":1,"entries":{"朱志香":{"reading":"じゅしか","accent":"じゅ","enabled":true,"instruction":"..."}}}` のような辞書）を取り込みます。
3. 左ペインで読み・アクセント・発音指示の追加／編集／削除・有効／無効を設定できます。右側の台詞インスペクターで「辞書適用後の読み上げ」を確認できます。
4. 設定内容はゲーム音声プロジェクトに保存され、**音声生成時だけ**適用されます。元のKS、ボイスID、原文、手動編集した読み上げテキスト・キャプションは変更しません。

**読み方辞書:** 長い単語を優先して、読み上げ用の文字列を一度だけ置換します（例えば「舞黒館」は「舞黒」と重複置換しません）。英数字からなる単語は別の英数字の途中で置換しません。

**アクセント辞書:** 指定された単語・別名が元の読み上げ文に存在する場合、`enabled: true` の項目の `instruction` をその行のTTS演技指示に追加します。`instruction` が空なら `accent` を短い指示に変換して追加します。読み方辞書に同一語がある場合は読み方辞書を優先します。アクセント指示はテキストプロンプトであり、**モデルによっては期待した音の高低を再現できないことがあります**。`enabled: false` はアクセント指示を無効にします。

生成済み音声に影響する辞書の変更がある場合、**その台詞だけ「要再生成」**に変更します。保存済み音声ファイルは削除しません。

配布ZIPの `examples/` に、今回の従来辞書と同じ形式のサンプルJSONを同梱しています。読み込む際はプロジェクト内の同じ種類の辞書を**置き換えます**（空のファイルを足してマージする方式ではありません）。

## v0.3.10: ゲーム音声の画面調整・プロジェクト名変更と複数クリップ移動

- **ゲーム音声のパネルサイズ**: 管理パネル／中央／ボイス編集の境界を左右に、原文／台詞一覧およびボイス編集／生成操作の境界を上下にドラッグできます。境界を選んで矢印キーでも調整できます。「原文を縮小して台詞を広げる」で一覧を広げ、「配置をリセット」または境界のダブルクリックで初期化します。サイズは同じブラウザで保持します。
- **名前変更**: ゲーム音声の作品名の下にある「プロジェクト名を変更」から変更できます。保存先のIDや台詞・音声は維持します。
- **ID変更通知**: 前回の一括確定によるID変更通知は右上の×で閉じられます。閉じた通知は同じブラウザで再表示せず、新しい変更内容があれば再表示します。
- **KS読み込み**: 「KSを仮登録」を「KSを読み込む」に変更しました。複数KSを読み込んだ後、IDを一括確定する流れは引き続き利用します。
- **マルチトラックの複数選択**: Ctrl（Macは⌘）＋クリックで選択を追加・解除、Shift＋クリックで同一トラックの範囲選択。選択済みクリップをドラッグすると間隔を保ってまとめて移動します。0秒より前には移動しません。右端のドラッグは対象1件の長さだけを変更します。
- **一括選択**: 上部の「全クリップ」「このトラックを全選択」「このクリップ以降を全選択」を利用できます。各トラック名の「以降を全選択」はそのトラックと下の全トラックを対象にします。すべて現在のシーン内だけが対象です。タイムラインにフォーカスがあるとCtrl/⌘＋Aで全選択、Escで選択解除できます。
- 複数移動も「戻す」「やり直す」に対応し、台詞に追従する素材も二重移動しません。
